# Мозок підбору майстрів

Як Zunor знаходить майстра для заявки: кого кличе й коли, що майстер бачить
у стрічці і кого першим бачить клієнт. Продуктові причини — у `MANIFESTO.md`
(«Районы и кольца рассылки», «Справедливий маркетплейс»); тут — як це
влаштовано в коді.

Роути імпортують **лише** з `$lib/server/dispatch` (`index.ts`).

## Потік

```
POST /api/jobs ─┐
перевідкриття ──┴─► startWaves ─► runWave (зараз) ─► dispatchJob
                         └─► таймери від createdAt ─► runWave ─► dispatchJob
                                                        └─ збій → повтор 15 с / 1 хв / 5 хв

старт процесу (hooks init) ─┐
/api/cron (раз на 30 хв) ───┴─► resumeDispatch ─► пропущена хвиля → runWave
                                              └─► майбутні хвилі → таймери

dispatchJob:  транзакція з advisory-локом на заявку
              ├─ decide ─ loadJob → stopReason
              │         └ loadCandidates → planWave (кільце, межа, бал, ліміт)
              └─ recordWave: журнал + сповіщення + Job.dispatchWave
              коміт → подія Pusher кожному
```

## Шари

| Файл                 | Що робить                                          | БД  |
| -------------------- | -------------------------------------------------- | --- |
| `config.ts`          | усі числа: хвилі, радіуси, бали, повтори           |     |
| `types.ts`           | типи; рішення й результат — розмічені обʼєднання   |     |
| `core/score.ts`      | бал майстра: розсилка й рекомендації               |     |
| `core/rings.ts`      | кільця й межа виїзду майстра                       |     |
| `core/waves.ts`      | номер хвилі, її час і ліміт за віком заявки        |     |
| `core/plan.ts`       | рішення хвилі з готових даних, останній дзвінок    |     |
| `core/recommend.ts`  | топ-3 відгуків + гарантований слот новачку         |     |
| `data/candidates.ts` | заявка й кандидати для хвилі                       | ✓   |
| `data/journal.ts`    | запис хвилі, журнал `DispatchEvent`, відзивчивість | ✓   |
| `decide.ts`          | читання + `core/plan` → рішення                    | ✓   |
| `dispatch.ts`        | лок → рішення → запис → коміт → події              | ✓   |
| `scheduler.ts`       | таймери хвиль і повтори в памʼяті процесу          |     |
| `recovery.ts`        | хвилі, які таймер не встиг                         | ✓   |
| `feed.ts`            | що майстер бачить у стрічці                        | ✓   |
| `proposals.ts`       | рекомендації клієнту з даними з БД                 | ✓   |

`core/` — чисті функції: дані на вході, рішення на виході, без БД, мережі
й годинника всередині (`now` передається). Уся логіка тестується там.

## Обіцянки, які тримає код

- **Кільця.** Хвиля кличе лише тих, хто в її радіусі від району заявки;
  радіус росте з кожною хвилею до всього міста.
- **Порожнє кільце не чекаємо.** Менше `MIN_RING_CANDIDATES` нових майстрів
  у кільці — одразу наступне.
- **Межа майстра тримається, доки майстрів досить.** «До 5 км» — кільця її
  не переступають. Лише остання хвиля, якщо заявку досі побачило менше
  `LAST_CALL_MIN_REACH` майстрів, кличе й тих, кому далеко (останній
  дзвінок): коли майстрів мало, заявка не має пропасти через відстань.
- **Невідомо ≠ поруч.** Майстер без району — лише в останньому кільці;
  заявка без району — кілець немає, кличемо як раніше.
- **Сповіщення доходить завжди.** Покликаний, його сповіщення й номер
  відпрацьованої хвилі пишуться однією транзакцією. Хвиля, що впала,
  повторюється; що не встиг таймер (рестарт, збій бази) — підхоплює
  відновлення на старті процесу й кроном.
- **Без дублів.** Рішення й запис — під локом заявки, журнал з unique
  `[jobId, masterId]`: хвилю можна кликати скільки завгодно разів.
- **Подія — після коміту.** Pusher не сповістить про те, чого немає в базі;
  збій події лише відкладає дзвіночок — сповіщення вже записане.
- **Стрічка не обганяє розсилку.** Свіжу заявку бачить лише покликаний,
  після останньої хвилі — усі, кому вона в межах виїзду. Покликаний бачить
  свою заявку завжди, навіть з-за меж.
- **Чого майстер не робить — не кличемо й не показуємо ніколи.** Уміння з
  анкети (`MasterProfile.metadata`, `$lib/masters/meta`) категорія
  перетворює на умови на `Job.metadata` (`$lib/categories/matching`).
  Відсів — у `loadCandidates` і в `masterFeedScope` (`skillsWhere`) однаково.
  Хто не відповідав на анкету — без умов, як раніше.
- **Відстань — у часі дороги.** З авто `travelKm = distanceKm ×
  VEHICLE_DISTANCE_FACTOR`: кільця й близькість рахуються від неї. Межа
  майстра (`acceptsDistance`) і журнал (`DispatchEvent.distanceKm`) — у
  кілометрах.
- **Нестача — як межа виїзду.** Заявці потрібне авто (сміття вивезти), а
  майстер явно сказав «без авто» — `withinReach: false`: його кличе лише
  останній дзвінок.
- **Зайнятому дорога дорожча** (`busyTravelPenalty`).
- **Формат роботи під обсяг заявки** (`crewFit`, ваги `CREW_FIT`). Обсяг —
  `Job.effort` 1–10 (`$lib/categories/effort`; для старих заявок —
  `matchingFor(category).effort(metadata)`), формат — `MasterProfile.crew`.
  На дуже велике першими компанії й бригади, на невелике — одинаки.
  Відсуває в черзі, а не відсіює.
- **Одні ваги для розсилки й для клієнта.** `masterScore` — спільна основа;
  у розсилці до неї додаються шанс новачку й штраф за недавні розсилки,
  у рекомендаціях новачку замість бонусу — гарантований слот у топі.

## Що де міняти

- Числа (радіуси, час хвиль, бали, повтори) — лише `config.ts`.
- Нове питання анкети, що звужує заявки категорії, — `categories/<категорія>/skills.ts`
  і запис у `categories/matching.ts`. Движок про слова категорії не знає.
- Новий фактор балу — `core/score.ts` і тест у `dispatch-scoring.test.ts`.
- Новий шлях, яким заявка перестає приймати відгуки, — виклич `cancelWaves`.
- Новий шлях, яким заявка (знову) відкривається, — `startWaves`.
- Новий шлях до стрічки майстра — через `masterFeedScope`.

## Тести

`src/tests/dispatch-*.test.ts`: `plan` (рішення хвилі, останній дзвінок),
`scoring`, `rings`, `recommend`, `feed` (видимість на справжніх заявках),
`scheduler` (час хвиль, повтори), `recovery` і `engine` (розсилка цілком на
моку Prisma: що читається, що й у якому порядку пишеться).
